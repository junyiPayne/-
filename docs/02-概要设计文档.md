# 运动健康系统概要设计文档

## 1. 文档说明

### 1.1 编写目的
本文档旨在描述运动健康系统的整体架构设计、功能模块划分、技术选型以及系统交互流程，为后续详细设计和开发提供指导。

### 1.2 适用范围
- 系统开发人员
- 系统测试人员
- 项目管理人员
- 系统维护人员

### 1.3 术语定义
- **运动健康系统**: Browser/Server架构的管理系统
- **API**: Application Programming Interface，应用程序编程接口
- **JWT**: JSON Web Token，用于身份验证的标准
- **RESTful**: 一种Web服务架构风格

## 2. 系统概述

### 2.1 系统背景
运动健康系统是一个基于浏览器/服务器架构的Web应用系统，旨在提供高效、安全、易用的管理功能。

### 2.2 系统目标
- 提供用户友好的Web界面
- 实现前后端分离架构
- 保证系统安全性和可扩展性
- 支持多用户并发访问
- 提供完善的权限管理机制

### 2.3 系统特点
- **前后端分离**: 前端使用Vue.js，后端使用Flask
- **RESTful API**: 标准化接口设计
- **JWT认证**: 无状态身份验证
- **响应式设计**: 支持多种设备访问
- **模块化设计**: 便于维护和扩展

## 3. 系统架构设计

### 3.1 总体架构

```

│           用户浏览器 (Browser)            │
│  ┌──────────┐  ┌──────────┐  ┌────────┐ │

│  │  前端    │  │   Plus   │  │   HTTP │ │
│  └────┬─────┘  └────┬─────┘  └────┬───┘ │
└───────┼─────────────┼─────────────┼─────┘
        │             │             │
        └─────────────┼─────────────┘
                      │ HTTP/HTTPS
        ┌─────────────▼─────────────┐
        │      Nginx (反向代理)      │
        └─────────────┬─────────────┘
                      │
        ┌─────────────▼─────────────┐

        │  ┌─────────────────────┐  │

        │  │  - 基础模块(生理)   │  │

        │  └──────────┬──────────┘  │
        │  ┌──────────▼──────────┐  │
```

### 3.2 技术架构

#### 3.2.1 前端技术栈
- **框架**: Vue.js 3 (Composition API)
- **UI组件库**: Element Plus
- **路由管理**: Vue Router 4
- **状态管理**: Pinia
- **HTTP客户端**: Axios
- **构建工具**: Vite
- **图表库**: ECharts (计划集成)

#### 3.2.2 后端技术栈
- **框架**: Flask 2.3+
- **ORM**: SQLAlchemy
- **API**: Flask-RESTful
- **认证**: Flask-JWT-Extended
- **验证**: Flask-Marshmallow
- **数据库**: MySQL 8.0+ (默认，适合大量用户)
- **PDF生成**: fpdf2 2.7.6
- **AI服务**: DeepSeek / 通义千问 API
- **HTTP客户端**: requests

#### 3.2.3 核心算法与模型
- **能量平衡**: 7700 kcal/kg 脂肪转化率
- **BMR公式**: Harris-Benedict 公式
- **AI模型**: DeepSeek-V3 / Qwen-Turbo (通过API调用)
- **提示词工程**: 角色扮演(运动生理学家) + 三段式输出

#### 3.2.4 开发工具
- **代码管理**: Git
- **API文档**: Swagger/OpenAPI
- **测试**: pytest (后端), Jest (前端)
- **代码规范**: ESLint, Pylint

## 4. 功能模块设计

### 4.1 用户管理模块

#### 4.1.1 功能描述
- 用户注册
- 用户登录/登出
- 用户信息管理
- 密码修改
- 用户列表查询

#### 4.1.2 主要接口
- `POST /api/auth/register` - 用户注册
- `POST /api/auth/login` - 用户登录
- `POST /api/auth/logout` - 用户登出
- `GET /api/users` - 获取用户列表
- `GET /api/users/{id}` - 获取用户详情
- `PUT /api/users/{id}` - 更新用户信息
- `DELETE /api/users/{id}` - 删除用户

### 4.2 权限管理模块

#### 4.2.1 功能描述
- 角色管理
- 权限分配
- 权限验证
- 菜单权限控制

#### 4.2.2 主要接口
- `GET /api/roles` - 获取角色列表
- `POST /api/roles` - 创建角色
- `PUT /api/roles/{id}` - 更新角色
- `DELETE /api/roles/{id}` - 删除角色
- `POST /api/roles/{id}/permissions` - 分配权限

### 4.3 业务管理模块

#### 4.3.1 功能描述
- 数据录入
- 数据查询
- 数据统计
- 数据导出

#### 4.3.2 主要接口
- `GET /api/business/data` - 查询业务数据
- `POST /api/business/data` - 创建业务数据
- `PUT /api/business/data/{id}` - 更新业务数据
- `DELETE /api/business/data/{id}` - 删除业务数据
- `GET /api/business/statistics` - 获取统计数据
- `GET /api/business/export` - 导出数据

### 4.4 用户档案模块（运动生理基础）

#### 4.4.1 功能描述
- 用户基础数据录入（性别、年龄、身高、体重、腰围、臀围、体脂率）
- 自动计算BMI、BMR、腰臀比、腰高比
- 健康状态评估（体重等级、体脂等级、肥胖评估）
- 头像上传和管理

#### 4.4.2 主要接口
- `GET /api/profile` - 获取用户档案
- `POST /api/profile` - 创建用户档案
- `PUT /api/profile` - 更新用户档案
- `POST /api/profile/avatar` - 上传头像

### 4.5 每日日志模块（运动生理基础）

#### 4.5.1 功能描述
- 饮食记录（热量、营养素比例、膳食纤维、酒精）
- 运动记录（类型、时长、强度、消耗）
- 身体指标记录（体重、腰围、臀围）
- 图片上传（食物照片）
- 自动计算净热量和预测体重变化
- 数据统计和趋势分析

#### 4.5.2 主要接口
- `GET /api/daily-log` - 获取日志列表
- `GET /api/daily-log/<date>` - 获取指定日期日志
- `POST /api/daily-log` - 创建/更新日志
- `GET /api/daily-log/statistics` - 获取统计数据
- `POST /api/daily-log/upload` - 上传图片

### 4.6 AI健康分析模块

#### 4.6.1 功能描述
- 健康风险评估（基于档案和日志数据）
- AI生成修正建议（三段式输出）
- 体重/体脂变化预测
- 支持DeepSeek和通义千问双API

#### 4.6.2 主要接口
- `POST /api/ai/health-assessment` - 获取AI健康评估
- `POST /api/ai/prediction` - 获取AI预测分析

### 4.7 报告管理模块

#### 4.7.1 功能描述
- PDF格式健康报告生成
- 报告预览功能
- 报告提交和历史记录
- 数据哈希对比，避免重复提交
- 角色权限控制（管理员查看全部，教师查看学生，学生查看自己）

#### 4.7.2 主要接口
- `GET /api/report/preview` - 预览报告（生成PDF）
- `POST /api/report/submit` - 提交报告
- `GET /api/report/list` - 获取报告列表
- `GET /api/report/view/<report_id>` - 查看报告详情

### 4.8 系统管理模块

#### 4.8.1 功能描述
- 数据备份
- 系统维护状态管理

#### 4.8.2 主要接口
- `POST /api/admin/backup` - 数据备份
- `GET /api/admin/maintenance` - 获取维护状态
- `POST /api/admin/maintenance` - 设置维护状态

## 5. 数据库设计

### 5.1 数据库选型
系统默认采用SQLite作为数据库（单文件，便于部署和迁移）。SQLite是一个轻量级的嵌入式数据库，无需单独的数据库服务器，适合中小型应用。

**特点：**
- 单文件数据库，便于备份和迁移
- 无需安装和配置数据库服务器
- 支持完整的SQL语法
- 支持事务和并发访问
- 可轻松迁移到PostgreSQL或MySQL（通过SQLAlchemy）

**数据库文件位置：** `backend/instance/bs_system.db`

### 5.2 主要数据表

#### 5.2.1 用户表 (users)
- id: 主键
- username: 用户名（唯一）
- email: 邮箱（唯一）
- password_hash: 密码哈希
- real_name: 真实姓名
- phone: 手机号
- avatar: 头像路径
- role_id: 角色ID
- is_active: 是否激活
- last_login: 最后登录时间
- created_at: 创建时间
- updated_at: 更新时间

#### 5.2.2 角色表 (roles)
- id: 主键
- name: 角色名称
- code: 角色代码（admin/teacher/student）
- description: 角色描述
- created_at: 创建时间

#### 5.2.3 权限表 (permissions)
- id: 主键
- name: 权限名称
- code: 权限代码
- description: 权限描述

#### 5.2.4 角色权限关联表 (role_permissions)
- role_id: 角色ID
- permission_id: 权限ID

#### 5.2.5 用户档案表 (user_profiles)
- id: 主键
- user_id: 用户ID（唯一）
- gender: 性别
- birthday: 出生日期
- age: 年龄
- height_cm: 身高(cm)
- weight_kg: 体重(kg)
- waist_cm: 腰围(cm)
- hip_cm: 臀围(cm)
- body_fat_percent: 体脂百分比
- bmi: BMI值（计算字段）
- bmr: 基础代谢率（计算字段）
- whr: 腰臀比（计算字段）
- whtr: 腰高比（计算字段）
- weight_category: 体重等级
- body_fat_category: 体脂等级
- created_at: 创建时间
- updated_at: 更新时间

#### 5.2.6 每日日志表 (daily_logs)
- id: 主键
- user_id: 用户ID
- log_date: 日志日期
- calorie_intake: 摄入热量
- carb_percent: 碳水百分比
- protein_percent: 蛋白质百分比
- fat_percent: 脂肪百分比
- fiber_grams: 膳食纤维(克)
- alcohol_grams: 酒精(克)
- food_images: 食物图片（JSON）
- exercise_type: 运动类型
- exercise_duration: 运动时长(分钟)
- exercise_intensity: 运动强度
- calorie_expenditure: 消耗热量
- daily_weight: 当日体重
- daily_waist: 当日腰围
- daily_hip: 当日臀围
- net_calorie: 净热量（计算字段）
- predicted_weight_change: 预测体重变化（计算字段）
- created_at: 创建时间
- updated_at: 更新时间

#### 5.2.7 报告表 (reports)
- id: 主键
- user_id: 用户ID（唯一，每个用户只有一个报告）
- title: 报告标题
- file_path: 文件路径（保留字段）
- pdf_content: PDF二进制内容
- data_hash: 数据哈希值（用于判断是否有变化）
- status: 状态（submitted/reviewed）
- created_at: 创建时间
- updated_at: 更新时间

#### 5.2.8 报告历史表 (report_history)
- id: 主键
- report_id: 报告ID
- modified_by_id: 修改者ID
- action: 操作类型（created/updated）
- description: 修改描述
- created_at: 创建时间

#### 5.2.9 业务数据表 (business_data)
- id: 主键
- title: 标题
- content: 内容
- creator_id: 创建者ID
- status: 状态
- created_at: 创建时间
- updated_at: 更新时间

## 6. 安全设计

### 6.1 身份认证
- 使用JWT Token进行无状态认证
- Token有效期设置为24小时
- 支持Token刷新机制

### 6.2 权限控制
- 基于角色的访问控制(RBAC)
- API级别的权限验证
- 前端路由权限控制

### 6.3 数据安全
- 密码使用bcrypt加密存储
- 敏感数据传输使用HTTPS
- SQL注入防护(使用ORM)
- XSS攻击防护
- CSRF防护

### 6.4 接口安全
- API限流
- 请求参数验证
- 异常统一处理

## 7. 接口设计规范

### 7.1 RESTful规范
- 使用HTTP动词表示操作
- 使用名词表示资源
- 使用状态码表示结果
- 统一的响应格式

### 7.2 响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {
    // 数据内容
  },
  "timestamp": "2024-01-01T00:00:00Z"
}
```

### 7.3 错误码定义
- 200: 成功
- 400: 请求参数错误
- 401: 未授权
- 403: 无权限
- 404: 资源不存在
- 500: 服务器错误
